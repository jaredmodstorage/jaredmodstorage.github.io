The AI Filled the Missing Readings. Which Values Were Actually Observed?

A smooth facility time series can hide a dangerous substitution: values generated to bridge a data gap being presented as if a sensor actually reported them.

By Jared Mastroianni10 min read

Research synthesis, drafting and quality assurance were AI-assisted under Jared Mastroianni’s byline. Fictional examples are instructional, not observed results.

A climate dashboard shows a clean line from 72 degrees to 78 degrees. The artificial intelligence assistant summarizes the period as a steady six-degree rise, recommends routine monitoring and moves on.

There is one problem: the sensor stopped reporting for ten minutes. Two points in the middle of that line were generated by a gap-filling method. They may be useful estimates. They are not observations.

That distinction can disappear quickly. A database stores the generated values in the same numeric column as the reported readings. A chart draws one continuous line. A language model receives a table with timestamps and numbers but no value-class field. By the time the assistant explains what happened, the gap has become a fact the facility never produced.

Self-storage and commercial real estate operators should treat this as an architecture problem, not a wording problem. The system needs to preserve the difference among an observed value, a corrected observation, an imputed estimate, an interpolated point, a forecast and an unknown. A model should never be asked to recover that difference from context after the data pipeline has erased it.

Missing is an operating state

Missing data is not zero, normal or unchanged. It means the expected observation is unavailable under the current evidence boundary.

The cause may be a sensor outage, a network interruption, a delayed integration, a mapping defect, a rejected quality check or a schedule that never required a reading in the first place. Those conditions have different owners and different consequences. Replacing all of them with a number may make a report easier to read while making the operating condition harder to understand.

The first control is therefore a visible gap record. It should identify the facility, asset, measurement type, expected cadence, interval, expected sample count, observed sample count, missing sample count, source state and quality state. Preserve the raw records and the fact that no record arrived for the missing interval.

This is not an argument against estimation. Interpolation, imputation and other statistical methods can support analysis when their assumptions fit the intended use. NIST published a guide to missing-data methods more than two decades ago; the lasting lesson is that the method is a declared analytical choice, not a recovered observation.[^1] The operational mistake is allowing the choice to disappear.

Give every value a class

A safe facility-data contract should require an explicit value class before a number can enter an AI decision path. A useful starting set is:

  • observed: emitted by the identified source for the stated asset, time and measurement;
  • observed-corrected: an observation changed through a governed correction process, with the original retained;
  • imputed: generated to replace a missing value using a declared method;
  • interpolated: generated between known points under stated assumptions;
  • derived: calculated from other values, such as an average or rate;
  • forecast: an estimate about a future interval;
  • unknown: no eligible value exists for the intended use.

These classes describe provenance. They do not declare that a value is accurate, safe or fit for a decision. An observed reading can be wrong because of a failed device or bad mapping. An imputed value can be statistically reasonable for a portfolio trend. The point is to stop one class from impersonating another.

The U.S. Geological Survey's data-management guidance offers a practical analogue: quality or usability indicators should sit with the individual data, and qualifier codes can identify estimated or interpolated values beside the numbers they qualify.[^2] That guidance was not written for self-storage AI and does not prescribe this control. It reinforces the design principle that data quality should travel with the value instead of living in a distant note.

Preserve the generation activity

Every generated value needs a receipt. At minimum, retain:

  • the missing interval and original source references;
  • the input observations actually used;
  • method identity, version and owner;
  • parameters, assumptions and maximum permitted gap;
  • the generated value and its uncertainty representation;
  • the time the method ran;
  • the model, code or service version that ran it;
  • the uses for which the result is eligible;
  • downstream artifacts that consumed it; and
  • the correction path if a late observation arrives.

W3C PROV-O supplies general vocabulary for connecting entities, activities and responsible agents through relations such as used, wasGeneratedBy and wasDerivedFrom.[^3] It does not decide whether an estimate is acceptable for an operating action. It does provide a sound way to retain the fact that the estimate was produced by a transformation from named inputs.

Do not overwrite the empty slot in the raw series. Store the generated series as a separate version or projection. The presentation layer can display a continuous line, but the line style, tooltip, export and API response should preserve which segments are observed and which are generated. If the chart shows a dotted segment but the CSV export drops the flag, the control is cosmetic.

Keep the model out of the measurement role

Language models can help explain a gap, compare eligible methods, draft a review note or summarize a validated analysis. They should not invent the missing reading because the prompt says “complete the series.”

NIST's Generative AI Profile describes confabulation as confidently presented erroneous or false content and notes the risk when people act on it in consequential settings.[^4] A fluent completion can be useful in creative work. In a facility record, a plausible number still needs a declared generation path and decision boundary.

Place deterministic controls before the model sees the series:

  1. Validate facility, asset, measurement, unit and time identity.
  2. Calculate coverage from expected and observed samples.
  3. Assign value classes and quality states.
  4. Apply an approved method only if the gap, inputs and intended use meet its contract.
  5. Propagate generated-value flags into every downstream representation.
  6. Evaluate decision eligibility outside the model.
  7. Hand back the case when required evidence remains unavailable.

The assistant may then say, “Two of six expected readings are missing; two displayed values are interpolated under method TEMP-LINEAR-2.1; the series is eligible for trend visualization but not for declaring the corridor condition during the gap.” That is more useful than a smooth answer that hides the evidence boundary.

Do not let presentation rewrite history

The raw timeline and the analytical timeline should remain separate even when they appear on the same screen. The raw timeline answers, “What did the identified source report?” The analytical timeline answers, “What did a named method generate from the information available?” A third record should capture what the decision process actually admitted.

That separation matters when a manager reviews an earlier decision. The latest chart may contain corrected observations that were unavailable at the time. Replaying the old decision against today's cleaned series can produce a useful comparison, but it cannot prove what the system knew then. Preserve the original input manifest, gap state, generated-series version and decision receipt. Label a later comparison as a reconstruction or counterfactual.

The same rule applies to customer-facing or maintenance language. “The sensor stayed below 80°F” is an observation claim. “The approved interpolation remained below 80°F” is a method claim. “No eligible observation establishes the interval” is often the most accurate operating statement. The interface should make those sentences difficult to confuse.

Bind eligibility to the use

An estimate is not globally safe or unsafe. Eligibility depends on the decision.

A short interpolation may be acceptable for a low-consequence visualization. The same value may be ineligible for declaring that a climate condition remained within an operating limit, closing a customer complaint, changing equipment settings, dispatching a vendor or evaluating an employee. Those decisions may require direct observation, corroborating evidence, a qualified technical determination or a governing-source readback.

Define eligibility as a policy result with fields for purpose, consequence class, maximum gap, minimum observed coverage, permitted methods, required uncertainty, corroboration and human authority. Include unknown and handback results. A confidence score should not convert an ineligible estimate into evidence.

The NIST AI Risk Management Framework identifies valid and reliable performance, accountability and transparency as important trustworthiness characteristics and ties them to datasets, models, organizational decisions and human interaction.[^5] It is voluntary, cross-industry guidance, not a self-storage standard. Applied here, it supports evaluating the entire decision path rather than treating a model's output quality as the only control.

Watch the boundary after deployment

This failure can reappear even after the schema is correct. A connector update may drop the value-class column. A dashboard export may flatten observed and generated rows. A retrieval pipeline may exclude quality metadata to save tokens. A prompt revision may ask the model to “fill blanks” before summarizing. A late source observation may arrive without invalidating the estimate that replaced it.

Post-deployment monitoring should therefore measure more than model errors. Track:

  • missing-sample rate by source, facility, asset and measurement;
  • generated-value rate by method and intended use;
  • generated values presented without their class;
  • gaps exceeding the method's approved duration;
  • high-consequence decisions exposed to generated values;
  • late observations that conflict with earlier estimates;
  • downstream artifacts awaiting correction; and
  • handbacks that remain unowned or overdue.

NIST AI 800-4, published in March 2026, organizes challenges in monitoring deployed AI systems and highlights issues such as dynamic inputs, drift, fragmented logging and the need to combine automated and human-validated monitoring.[^6] The report maps challenges and open questions; it does not validate this gate or establish that a particular operator has implemented it.

A fictional facility example

Consider Stonegate Hollow Storage, an explicitly fictional teaching facility. No real facility, customer, employee, vendor, system, model, incident or result is represented.

A fictional corridor sensor is expected to report every five minutes. At 2:00 p.m. it reports 72°F and at 2:05 p.m. it reports 73°F. The 2:10 and 2:15 readings are missing. At 2:20 p.m. it reports 78°F. A fictional analysis service creates 74.7°F and 76.3°F by linear interpolation and labels them interpolated under method TEMP-LINEAR-2.1.

The values may be displayed in a diagnostic trend, with the gap and method visible. They may not be described as sensor readings. The fictional policy also blocks them from proving that the corridor remained within a target range during the gap. The AI assistant receives the raw observations, generated series, coverage calculation and policy result. It prepares a review note and hands the unresolved interval to the fictional facilities owner. No equipment action, vendor dispatch, customer communication or closure occurs in the example.

If delayed observations later arrive, the system does not silently replace history. It creates a correction record, compares the observed and generated values, identifies every dependent summary or decision, and routes material corrections to their owners. The original estimate remains reconstructable as the information available at the earlier decision time.

Use the integrity gate

The accompanying AI Observation-Gap and Imputation Integrity Gate gives operators and architects one record for the gap, raw coverage, generation method, value class, eligible use, prohibited use, handback and correction propagation. The blank CSV supports implementation planning; the Stonegate Hollow rows are explicitly fictional teaching data.

Start with one measurement path and one low-consequence use. Test complete data, isolated gaps, long gaps, delayed observations, source conflicts, unit conflicts, connector field loss and exports that strip quality flags. Require every downstream consumer to preserve the value class. Only then consider broader use.

A complete line is not necessarily a complete record. Responsible AI architecture makes the missing interval visible, makes every generated value identify itself and keeps an estimate from becoming an observation simply because the interface looks smoother that way.
